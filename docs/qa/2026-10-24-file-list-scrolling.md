# 大量文件连续滚动流畅度修复

范围：v2.0.3 发布后的 main 本地工作区，版本号仍为 2.0.3 (16)，本轮随源码提交，未单独发布安装包。

## 验证口径

用户反馈的是滑动时的掉帧、顿挫感。上一轮 2,000 → 17 的数字只是状态通知次数，首尾条目显示检查也只证明功能完整，均不能证明滚动流畅。本轮用相同场景的主线程调度与同步布局耗时判断改善；旧 `IconGridViewport` 和滚动偏移发布器已经删除。

测试命令为应用的 `--selftest-scroll <报告路径> --skip-device-tests`。真实窗口 1500 × 820，包含 1,200 个有效空 ZIP，以 60 Hz 的计划节奏进行 360 次连续偏移更新，每轮往返 3,600 点，共三轮。每轮记录 359 个主线程调度间隔与 360 次滚动/同步布局耗时。采集期间不读取辅助功能界面树，也不并行编译。

这是主线程调度与布局的本机对比，不是 GPU 或屏幕实际 FPS，不能据此承诺所有设备始终达到 60 FPS。

## 最终实现

- 原生 `NSScrollView` 保留平滑滚动与惯性；只维护可见区域和附近的行。
- 有限的行宿主池循环复用 `NSHostingView`，离屏行重新分配到新位置时保留控件身份，不在每次跨行时重新创建整行视图。额外闲置宿主最多保留四个。
- 磁贴使用固定尺寸的原生图标、文字与选中状态显示，复用时更新内容；图片到达时直接更新 `NSImageView`，避免触发 SwiftUI 文本/栈布局。保留共享的点击、双击、拖动与右键菜单包装。
- 系统图标按路径、修改时间、大小与尺寸缓存，预算 12 MiB，最多两个并发请求；媒体缩略图继续使用原有的独立管线。修改内容或复用磁贴时取消过期图片任务，内存压力时可释放缓存。
- 默认应用缺失结果也缓存，避免同类文件反复查询 LaunchServices；关联设置变更仍刷新徽标。
- 详细列表与图标网格按实际数据源变化处理待定位文件，避免重绘时遍历全部 ID；原生网格等待有效视口尺寸后定位。

## 连续滚动结果

基线为上一轮已安装的本地修复版，已经包含图标缓存与按行发布优化。最终数据来自本轮正式优化通用构建的独立测试副本。

| 轮次 | 基线主线程间隔 p95 | 最终构建 p95 | 超过 25 ms 的间隔 |
| --- | ---: | ---: | ---: |
| 1 | 59.67 ms | 18.55 ms | 100 → 3 |
| 2 | 51.54 ms | 17.19 ms | 82 → 0 |
| 3 | 43.11 ms | 17.56 ms | 62 → 0 |

三轮共 1,077 个调度间隔，超过 25 ms 从 **244 次降至 3 次**；超过 50 ms 从 **48 次降至 0 次**。最终首轮最大间隔约 40.1 ms，后两轮最大约 18.1 / 18.8 ms。最终同步滚动/布局耗时的 p95 约 10.0–10.4 ms。

## 悬停滚动残影的后续修复

用户继续反馈鼠标留在文件区时，滚动出现黑影。在上述已安装版的真实压缩包分类复现了多个灰色悬停底色同时残留，修复前记录为 `hover-before.png`。原实现由每个可复用磁贴自行保存 `mouseEntered` / `mouseExited` 状态；滚动移动和复用磁贴时，进出事件并不始终成对送达，导致旧磁贴保留悬停状态。

改由原生网格文档视图统一追踪鼠标，且每次滚动布局完成后根据当前窗口鼠标位置重新定位磁贴。最多保留一个悬停目标，旧目标、隐藏行和移出网格都会清理；复用为新文件时即使视图身份不变，也重新应用当前悬停状态。磁贴底色和边框更新关闭 Core Animation 隐式动画，避免滚动途中淡出拖影。原有颜色、选择样式、点击和菜单保持不变。

界面回归增加真实窗口中悬停定位、悬停转移、移出清理和长距离滚动复用后的底色数量检查。四项新增断言通过，本轮界面测试共 38 项断言通过，0 失败。原有合成双击段的限制仍同上；另在已安装版真实分类页验证了右键菜单、双击 `dist/WinFile-2.0.3.zip` 预览及关闭返回。

同一 1,200 文件场景再次采集三轮性能，主线程调度间隔 p95 分别为 17.37 / 17.51 / 17.59 ms，同步滚动布局 p95 为 11.52 / 11.19 / 11.03 ms。三轮超过 25 ms 共 12 次，超过 50 ms 共 7 次，仍有个别长间隔；本轮结果不表示消除所有卡顿或实际屏幕 FPS。没有重复运行未受本次纯视图修改影响的全量逻辑测试。
