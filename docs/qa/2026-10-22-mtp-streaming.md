# MTP 视频内存流式播放

> 发布归档：以下为开发过程的原始验收记录，其中“未发布”和旧版本号描述当时状态；最终代码随 v1.4.0 (10) 发布。视频最终行为以 [内存流式播放记录](2026-10-22-mtp-streaming.md) 为准。

日期：2026-10-22。当前本地实现，尚未提交或发布。

## 行为与实现

- 安卓视频双击、右键打开和空格预览统一使用内置 AVPlayerView。普通双击自动播放，空格先预览；一次处理一个视频。其他文档仍使用已有的本机只读副本机制；手动下载保持原有行为。
- 自定义 URL 的 AVAssetResourceLoader 接收 AVFoundation 的字节范围请求，经唯一 MTP helper 的 LIBMTP_GetPartialObject 分段读取。没有本机 HTTP 服务，不使用 ADB，没有创建完整视频文件，也不自动下载回退。
- helper 每次最多读取 1 MiB，通过管道返回 Base64 数据；逐次校验设备序列号和 USB 连接，以及文件对象 ID、存储 ID、大小和修改时间。文件或连接变化时失败，避免混读。大于 4 GiB 的虚拟偏移由模型测试覆盖；实际大文件能力受设备 64 位分段读取支持限制。
- 共享 LRU 内存缓存硬上限 32 MiB，按播放实例隔离；关闭或连接变化时取消请求并释放自身缓存。此上限只针对 WinFile 的共享视频数据缓存，不代表播放器解码帧或软件总内存上限。没有承诺操作系统交换内存、诊断日志等完全零写盘。
- 拖动进度取消旧范围请求；内容信息先于数据返回，明确支持字节范围并正确处理读取至 EOF、短块、跨块和请求取消。缓存、在途块及播放器保有的数据均在内存中，未使用视频磁盘缓存。
- 设备不支持分段读取、文件变化或编码不兼容会显示错误，不自动完整下载。外部播放器和系统不支持的格式需用户手动下载。旧的非视频磁盘缓存规则及已有缓存不在此次迁移中主动删除。
