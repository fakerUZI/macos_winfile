# 安卓图片关闭后 MTP 不可用回归

首个复现：2026-10-22。最终验收：2026-10-23。范围：v1.4.0 (10) 之后的修复，归档于 v1.4.1 (11)。以下“本地修复”与旧版本号描述开发验收时的状态，最终发行验证见 [v1.4.1 更新记录](../releases/v1.4.1.md)。

## 证据与复现

- 原日志：23:42:08 双击安卓相机目录的图片；23:42:12 起连续出现 `mtp.library op=scan codes=claim:-3`，设备从已识别名称变成 USB 临时标识与 unavailable 状态。出现故障时 macOS Preview、mscamerad-xpc 和 ptpcamerad 正在运行。
- 本机 libusb 1.0.30 的 Darwin 后端将 `kIOReturnExclusiveAccess` 映射为 `LIBUSB_ERROR_ACCESS`（-3）。因此这里的 -3 不能直接解释为手机未解锁，也不意味着完整磁盘访问权限缺失。
- 23:44:23，完全退出 Preview 后，同一个 WinFile 进程自动重新识别原设备。没有重启 WinFile、杀系统守护进程或更改 USB 权限。
- 用唯一 `WinFile-Image-...` 目录、公开应用图标生成的 sample.png 再次复现：双击由 Preview 打开，关闭图片窗口后扫描持续 claim:-3，原目录变成“安卓设备已断开”；完全退出 Preview 后自动恢复原目录。没有再次打开个人照片。

## 修复

- 安卓图片与 PDF 的双击、右键打开通过已存在的 Quick Look 面板显示本机只读副本，避免自动启动 Preview 与相机导入浏览器；空格预览保持一致。多张图片可在同一预览中切换，混合选择图片和普通文档会分别交给内置预览与外部默认应用。
- 普通文档默认打开、本地文件关联、视频 MTP 内存播放保持原有行为；若要用外部应用编辑图片/PDF，可手动下载。
- 同一个 USB 连接暂时无法建立会话时，保留已知名称和真实序列号用于页面展示，立即清除就绪状态与存储位置。断开后不继承旧身份；成功扫描到另一台真实设备时不重定向旧页签。此显示保留不会给底层写入添加重试或跳过序列号校验。
- 设备页状态随可用性更新，避免停在“正在读取设备存储”；占用提示说明 Preview / Photos / Image Capture，以及“关闭窗口”不等于“退出应用”。
- 不强制退出用户应用，不杀 ptpcamerad，不修改系统驱动或 USB 设置。用户主动启动外部相机导入应用时仍可能发生 USB 独占，释放占用后自动恢复。
