## 本轮确定的代码问题与修复

1. **临时身份更新后设备页停留旧身份。** helper 在 MTP 会话暂时不可用时，以 USB 标识作为临时序列号；成功后返回真实序列号。原 BrowserModel 的设备页没有处理这个更新，可能继续显示已断开。本轮只将同一 USB 连接的临时设备页升级到真实身份；同时修正 loadAndroidDevice 对已有安卓页忽略新序列号的条件。已经绑定真实序列号的页签不会自动指向另一台设备。
2. **读取沿用过期 USB 地址。** 同序列号重连产生新 USB 地址后，缓存可能在后台刷新前仍指向旧地址。目录和属性读取若返回 noDevice/deviceChanged，会重新扫描原序列号；仅在找到新的 USB 地址时再尝试一次。不重放上传、下载、新建、移动、重命名或删除；原设备缺席时不会改为操作新设备。
3. **诊断缺失且重启丢失证据。** 日志增加 USB 出现/消失、设备状态与存储 ID 变化、临时身份升级、只读重试、MTP 请求错误码和耗时。底层 stderr 只提取白名单 USB/PTP 错误码及占用标记，不保留原始文件名/输出。设备序列号在新增传输摘要中使用哈希标识；历史普通导航日志的内容规则没有改变。
4. **日志有界保留。** 重启保留三份历史，单文件达到 2 MiB 时轮换。清除诊断日志会同时清除历史文件。测试模式日志写入独立临时目录，避免混入正常使用日志。
5. 会话暂时打不开的提示与“解锁”分开，侧栏使用“等待文件传输就绪”，不再仅凭会话失败推断锁屏。
