# WinFile v1.3.4

版本 `1.3.4`，构建号 `9`。本次完善内置文件夹选择、降低大目录浏览的内存占用，并修复文件定位与目录错误恢复。

## 内置文件夹选择

- 「打开文件夹」使用 WinFile 自己的选择器，支持浏览、输入路径、显示隐藏目录和 ⌘ 多选。每个选中的目录在新页签打开，首个激活，保留原页签。
- 收藏、启动目录、微信目录、解压位置、安卓下载位置及重复文件扫描范围统一使用内置选择器。
- 左上角可折叠整个左侧菜单，重新展开后保留原宽度；与右侧详细信息独立控制。

## 浏览性能与内存

- 大图标视图只创建可见区域及附近的磁贴，保留选择、右键、双击与拖放。
- 缩略图最多并发生成 4 张，合并重复请求；LRU 缓存预算 64 MiB、最多 800 项，取消离屏请求并在内存压力下回收。仍在显示的图片和系统 Quick Look 进程不在该缓存预算内。
- 清理模块首次访问才初始化。超过最近 3 个页签且闲置至少 60 秒的本地目录、搜索和分类结果可回收，返回时按原条件读取；保留清理选择和进行中的操作。
- 同一组 1000 张合成 PNG、4 个页签和相同窗口配置下，物理内存占用从约 337 M 降至 80 M（约 76%）。这是单机合成负载结果，不代表所有文件库或长期运行场景。

## 导航与扫描修复

- 地址解析与路径补全在后台执行；无效路径保留当前位置，输入文件路径会进入父目录并选中对应文件。
- 修复大目录中定位文件未滚动到目标，以及离屏图标拦截地址栏双击的问题。
- 目录不存在、权限不足、失效链接或磁盘未挂载时保留错误页面，支持重试。
- 微信扫描默认最多保留 20,000 个候选、遍历 200,000 项；达到上限明确标注部分结果与部分占用，可手动提高上限重新扫描，最高 200,000 个候选、2,000,000 项遍历。不读取或解密聊天数据库。

## 验证与升级

- CLI 1070 项检查通过；Apple Silicon 与 Intel/Rosetta 实际应用包各 1075 项检查通过。
- 真实窗口页签回归、内置选择器多选、1000 项图标滚动和定位、双击、右键与目录错误恢复验收通过。
- 本轮使用 `--skip-device-tests`，未运行真实安卓设备传输。
- macOS 13+，同一个安装包支持 Apple Silicon 和 Intel。v1.2.0 及以上可在应用内检查更新；更早版本需手动升级一次。
- 当前发行包使用 ad-hoc 签名，未进行 Apple 公证。首次打开请参阅 [安装说明](https://github.com/fakerUZI/macos_winfile#安装)。更新包与更新源使用既有 Ed25519 密钥签名验证。

```bash
curl -fsSL https://raw.githubusercontent.com/fakerUZI/macos_winfile/main/install.sh | /bin/bash
```

## English

WinFile 1.3.4 (build 9) adds consistent in-app folder selection and improves large-folder browsing, memory use and navigation recovery.

- Open Folder supports path entry, hidden folders and multi-selection. Each chosen directory opens in a new tab; the first becomes active and the original tab stays open. Favorites, startup folders, extraction destinations, Android downloads, WeChat directories and duplicate-scan scopes also use the in-app picker.
- Collapse the left sidebar independently of the inspector, preserving its preferred width.
- Render only visible and nearby icon rows. Generate up to four thumbnails concurrently, coalesce duplicate requests and reclaim the 64 MiB / 800-item LRU cache under memory pressure. Displayed images and the system Quick Look process are outside this cache budget.
- Initialize cleanup modules on demand and reclaim reloadable local data in tabs outside the three most recent tabs after 60 seconds of inactivity. Active operations and cleanup selections are retained.
- Resolve and complete paths off the main thread. Invalid paths keep the current location; file paths select and scroll to the target in its parent directory. Directory failures remain visible with a retry action. Offscreen tiles no longer intercept address-bar double-clicks.
- WeChat scans explicitly identify partial results and storage totals at the default limits of 20,000 candidates / 200,000 visited items; users can raise those limits up to 200,000 / 2,000,000. Chat databases are not read or decrypted.
- In one controlled 1000-image synthetic load with the same four tabs and window configuration, physical footprint fell from about 337 M to 80 M (~76%). Results vary with files and usage.

Validation: 1070 CLI checks and 1075 checks in each of the Apple Silicon and Intel/Rosetta app bundles passed, alongside real-window navigation and tab regressions. Physical Android transfers were excluded. Requires macOS 13+; in-app updating is available from v1.2.0. The app is ad-hoc signed and not Apple-notarized; update archives and feeds are verified using the existing Ed25519 key.
